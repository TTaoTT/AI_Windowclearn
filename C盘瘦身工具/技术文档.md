## 1. 总体架构（分层）

```
┌──────────────────────────────────────────────────────────┐
│  UI 层（桌面 GUI）                                          │
│   - 空间树图 / 目录树 / 类型分布                            │
│   - 清理清单 / 迁移清单（风险分级、预览）                   │
│   - 防再生设置面板 / 计划任务 / 报告                        │
└──────────────────────────────────────────────────────────┘
                          │  调用
┌──────────────────────────────────────────────────────────┐
│  业务引擎层（与 OS 无关的核心逻辑）                         │
│   - 扫描引擎       - 规则引擎       - 清理引擎             │
│   - 迁移引擎       - 防再生引擎     - 调度/报告引擎        │
│   - 安全/回滚管理器（还原点、回收站、日志、白黑名单）       │
└──────────────────────────────────────────────────────────┘
                          │  适配
┌──────────────────────────────────────────────────────────┐
│  系统适配层（Windows 专用）                                 │
│   - NTFS MFT/USN 读取   - 符号链接/Junction 创建           │
│   - 注册表/Known Folders - CBS/DISM/CompactOS/cleanmgr     │
│   - VSS/还原点/回收站    - 进程管理(taskkill)              │
│   - 任务计划程序(Win32_ScheduledJob / Task Scheduler COM)  │
└──────────────────────────────────────────────────────────┘
```

**设计原则**
1. 业务引擎层不依赖具体 GUI 框架，可被 CLI / GUI 共用 → 利于测试与后续 CI。
2. 系统适配层用统一接口封装（如 `IFileSystem`、`IRegistry`、`ISymbolicLink`），便于在 Python/C#/Rust 三方案下分别实现。
3. 所有"危险操作"走安全管理器统一闸门：权限校验 → 还原点 → 回收站/备份 → 执行 → 记日志。

## 2. 技术栈对比与推荐

交付形态已定为**桌面 GUI 应用**。以下三方案均能满足需求，差异在开发效率、原生能力、分发体积。

| 维度 | A. Python + PySide6 | B. C# / .NET (WPF) | C. Rust + Tauri |
|------|---------------------|--------------------|-----------------|
| GUI | PySide6（Qt），跨平台思维 | WPF/XAML，原生 Windows 外观 | Web 前端（React/Svelte）+ 原生壳 |
| Windows 系统 API | `pywin32` + `ctypes` 调用；MFT 需 `ctypes` 封装或调 `fsutil` | 一等公民（P/Invoke、WMI、CBS/DISM 官方库） | `windows-rs` crate / `std::os::windows`；MFT 用 `DeviceIoControl` |
| 符号链接/Junction | `os.symlink` + `ctypes`（`CreateSymbolicLinkW`） | `mklink` / `System.IO` + P/Invoke | `std::os::windows::fs::symlink_*` |
| 扫描性能 | MFT 直读需自封装，略复杂 | 易用，性能好 | 最佳（无 GC、零成本抽象） |
| 分发 | PyInstaller 打包（体积较大 ~30-80MB） | 单 exe（.NET 自包含 ~50-120MB，或用 runtime） | 单文件最小（~5-15MB） |
| 与作者技术栈契合 | 高（Darker 熟悉 Python/JS） | 低（需学 C#） | 中（JS 做 UI，Rust 新学） |
| 生态/示例 | 丰富（BleachBit 即用 Python） | 丰富（Dism++ 系思路接近） | 较少但增长快 |
| 推荐度 | ★★★★（推荐首发） | ★★★★（最原生） | ★★★（长期最优） |

### 推荐路径
- **首版（MVP）采用方案 A：Python + PySide6 + pywin32。**
  - 理由：契合作者现有 Python/JS 能力、迭代最快、规则引擎/扫描/迁移逻辑用 Python 写得快且易测；BleachBit 等成熟项目已验证 Python 做清理器的可行性。
  - 分发：PyInstaller 打单 exe；MFT 直读通过 `ctypes` 封装 `DeviceIoControl(FSCTL_ENUM_USN_DATA)` 实现，回退到 `os.walk`。
- **演进可选**：若对原生体验/体积有强要求，可将系统适配层用 C# 重写或 Rust 重写，业务引擎层（规则/调度/报告）保持不变。

## 3. 模块设计

### 3.1 扫描引擎（Scanner）
- **NTFS 快速路径**：以管理员身份打开卷句柄 `\\.\C:`，用 `DeviceIoControl(FSCTL_ENUM_USN_DATA)` 遍历 MFT，O(1) 层级累加目录大小，秒级完成。需处理 `$MFT`、`$Bitmap` 等特殊文件与 junction 循环（`IO_REPARSE_TAG_MOUNT_POINT` 不递归）。
- **回退路径**：非 NTFS 或无权限时用 `os.walk` 递归，配合 ACL 读取过滤保护目录。
- **标签引擎**：扫描结果结合规则库给目录打"语义标签"（浏览器缓存/开发缓存/用户数据/系统），供 UI 高亮。
- **快照对比**：保存 `{path: size, mtime}` 基线，二次扫描 diff 出增量。

### 3.2 规则引擎（RuleEngine）
- 规则以 **YAML/JSON** 描述，分两类：
  - `clean_rules`：匹配路径/通配/年龄/大小 → 风险等级 + 处理方式（recycle / delete / system_api）。
  - `migrate_rules`：匹配目录 → 风险等级（L1/L2/L3）+ 技术路径 + 关联进程名 + 前置条件。
- 规则含 `os_min`/`os_max` 字段做版本适配；社区可提交新规则（类 Dism++ Data.xml 思路）。
- 内置**黑名单**（`Windows/Installer`、`System32` 主体、`AppData/Local/Packages` 等）硬性拦截。

### 3.3 清理引擎（Cleaner）
- 安全删除：经 `IFileOperation`/`SHFileOperation` 送入**回收站**（保留可恢复）。
- 系统类清理调用官方通道：
  - Windows 更新缓存：停 `wuauserv`+`bits` → 删 `SoftwareDistribution\Download` → 重启服务。
  - WinSxS：`Dism.exe /Online /Cleanup-Image /StartComponentCleanup`（可选 `/ResetBase` 谨慎）。
  - 临时文件/缩略图：直接回收站删除。
  - 休眠：`powercfg -h off`（需确认）。
  - 旧备份/还原点：调用 `vssadmin` / 磁盘清理 COM，不手动删 `System Volume Information`。
- 重复文件：内容哈希（xxHash/SHA）比对，仅删副本，保留一份并可选硬链接去重。

### 3.4 迁移引擎（Migrator）
标准三步（关进程 → 复制 → 建链），全部经安全闸门：
1. **关进程**：按 `migrate_rules.associated_processes` 调 `taskkill /F /IM`。
2. **复制**：`robocopy <src> <dst> /E /COPYALL /R:0 /W:0 /MT:32 /ZB` 保留 ACL/时间戳/所有权；跨盘用 `/COPYALL`。
3. **删源 + 建链**：
   - L1（用户文件夹）：改注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders` 指向新路径（微软官方，零风险）。
   - L2/L3：`rmdir` 源 → `mklink /J <src> <dst>`（目录联接，仅本地卷、稳定、对软件透明）；跨盘或需符号链接时用 `mklink /D`（需启用开发者模式或管理员）。
4. **自检**：启动关联 exe 或校验关键文件读写；失败则自动回滚（删链接 + 数据搬回 / 或仅删链接因数据仍在 D 盘）。
5. **记录**：写入 `junction-manifest.json`（源/目标/类型/时间），用于统一回滚与排查。

> 注意：**禁用 junction 的对象**（写入规则黑名单）：杀软、VPN/内核驱动、反作弊游戏启动器、备份软件——避免更新器覆盖链接或循环。UWP/WSL 走系统官方"移动"通道，不手动 junction。

### 3.5 防再生引擎（Preventer）
逐项开关映射到具体系统改造：
- Storage Sense：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\StorageSense` 并触发。
- 用户文件夹重定向：改 `User Shell Folders`（同 3.4 L1）。
- 默认保存位置 / UWP 安装盘：`Settings` 对应注册表（`…\Storage\Config`）。
- NTFS 压缩：`compact.exe /c /s:<dir>` 定点目录。
- OneDrive 文件随选：配置 `FilesOnDemand` 策略。
- 开发环境：改环境变量（`npm_config_cache`、`CARGO_HOME`、`MAVEN_OPTS -Dmaven.repo.local`、`PIP_CACHE_DIR` 等）与配置文件，将其指向 D 盘集中目录。
- 浏览器下载路径：改 Chrome/Edge 策略或 `…\Default\Preferences` 中 `download.default_directory`。
- 每项开关记录"前值"，便于关闭时还原。

### 3.6 安全 / 回滚管理器（Safety）
- **权限**：程序清单 `requestedExecutionLevel=requireAdministrator`；非管理员时启动"安全子集"（仅扫描 + 安全清理 + 只读迁移预览）。
- **还原点**：关键批量操作前 `WmiExec` 调 `SystemRestore.CreateRestorePoint`（或 `vssadmin create shadow`）。
- **回收站**：默认软删；强删类明确提示不可逆。
- **事务日志**：SQLite 存储操作流水（id, time, type, target, size, result, rollback_cmd），可审计、可重放、可一键回滚。
- **二次确认**：影响 > 阈值或风险 ≥ 谨慎级，弹窗展示影响范围与可回收性。
- **占用文件处理**：`Restart Manager` / `taskkill` 释放；仍占用则跳过并提示，不破坏。

### 3.7 调度 / 报告引擎（Scheduler / Reporter）
- 调度：通过 Windows 任务计划程序 COM（`Schedule.Service`）或 `schtasks.exe` 注册周/月任务，调用本程序 CLI 子命令出报告。
- 报告：扫描结果 → 导出 CSV / HTML（含树图缩略、趋势曲线、可回收/可迁移汇总）。

## 4. 数据模型（草案）

```yaml
# rule.clean.yaml 示例
- id: windows_temp
  type: clean
  match:
    paths: ["C:\\Windows\\Temp\\*", "%TEMP%\\*"]
    age_days: 0
  risk: safe
  action: recycle            # recycle | delete | system_api
  os_min: "10.0"

# rule.migrate.yaml 示例
- id: user_downloads
  type: migrate
  match: { path: "%USERPROFILE%\\Downloads" }
  risk: L1
  method: shell_folder_redirect
  associated_processes: []
- id: appdata_tencent
  type: migrate
  match: { path: "%LOCALAPPDATA%\\Tencent" }
  risk: L2
  method: junction
  associated_processes: ["WeChat.exe", "QQ.exe"]
```

## 5. 关键技术点速查

| 目标 | 命令 / API |
|------|-----------|
| NTFS MFT 直读 | `DeviceIoControl(FSCTL_ENUM_USN_DATA)` via ctypes/pinvoke |
| 目录联接 | `mklink /J`（`CreateSymbolicLinkW`, `dwFlags=1`） |
| 符号链接 | `mklink /D`（需开发者模式/管理员） |
| 复制保留权限 | `robocopy /E /COPYALL /R:0 /MT:32` |
| WinSxS 回收 | `Dism /Online /Cleanup-Image /StartComponentCleanup` |
| 更新缓存清理 | 停 `wuauserv`+`bits` → 删 `SoftwareDistribution\Download` |
| 休眠关闭 | `powercfg -h off` |
| 用户文件夹重定向 | 改 `User Shell Folders` 注册表 |
| 还原点 | `SystemRestore.CreateRestorePoint`（WMI） |
| 回收站删除 | `IFileOperation::DeleteItem`（FOF_ALLOWUNDO） |
| 任务计划 | `Taskschd` COM / `schtasks.exe` |
| 结束进程 | `taskkill /F /IM <exe>` / Restart Manager |

## 7. 测试策略

- **单元**：规则解析、路径匹配、robocopy 参数生成、manifest 序列化。
- **集成（虚拟机快照）**：在干净 Win10/Win11 虚拟机执行清理/迁移，校验系统可启动、软件可运行、空间释放符合预期。
- **回归**：每次发布跑"黄金脚本"（清理临时文件→迁移 Downloads→回滚），断言系统无异常。
- **安全**：红线目录永不被匹配；任意删除可经回收站恢复；还原点可回退。
- **性能**：百 GB NTFS 盘扫描 < 10s 的基准测试。

## 8. 风险与缓解（工程视角）

- **MFT 直读复杂度**：Python 下 `ctypes` 封装 USN 有坑 → 先实现 `os.walk` 回退，MFT 作为性能优化后续补。
- **Junction 导致软件更新异常**：靠风险分级 + 关联进程关闭 + 自检 + manifest 回滚缓解；高风险对象禁迁。
- **UAC/权限**：清单提权 + 安全子集降级。
- **规则误判**：规则分级 + 社区复审 + 默认仅勾选 safe。

## 9. 附录 · 典型可清理 / 可迁移路径清单（参考）

**可清理（安全）**
- `C:\Windows\Temp\*`、`%TEMP%\*`、`%LOCALAPPDATA%\Temp\*`
- `C:\Windows\SoftwareDistribution\Download\*`
- `C:\Users\<u>\AppData\Local\Microsoft\Windows\Explorer\ThumbCache_*.db`
- `$Recycle.Bin`
- 浏览器缓存：`AppData\Local\Google\Chrome\User Data\*\Cache`、`AppData\Local\Microsoft\Edge\*\Cache`
- 应用缓存：`AppData\Local\Tencent\*\*`、Teams cache、`AppData\Local\CrashDumps\*`

**可迁移（按风险）**
- L1：`Downloads` `Desktop` `Documents` `Pictures` `Videos` `Music`
- L2：`AppData\Roaming\JetBrains`、`AppData\Local\JetBrains`、`AppData\Local\Google`、`AppData\Local\Microsoft\Edge`、`AppData\Local\Tencent`、`AppData\Roaming\Tencent`、`AppData\Local\Microsoft\Teams`、`.cargo`、`.rustup`、`.vscode`、`.npm`、`.m2`、`.gradle`、`AppData\Local\wsl`
- L3：第三方大型软件/游戏（无自带迁移者），如 `C:\Program Files\SomeGame`
- 系统通道：`AppData\Local\Packages`（UWP，设置→应用→移动）、WSL（`wsl --export`+重定位）

**不可动红线**
- `C:\Windows\Installer`、`C:\Windows\System32`（主体）、`C:\Program Files\*` 主体、`AppData\Local\Packages`（整体）、DriverStore/显卡驱动目录、`System Volume Information`
